# Avatar Recording Plan (a picture that talks instead of a webcam)

**Date:** 2026-09-22
**Spec:** `docs/superpowers/specs/2026-09-22-avatar-recording-design.md` (decisions A–I). It proceeds on the defaults for Q1, Q3, Q4 and Q5; Q2 is settled by construction (the image is the mode).
**Status:** Built and shipped in 0.3.0 (`5f0d7e7`). Tasks 1-5 done; Task 4 moved to the GL inset pad after its entry-gate measurement refused the overlay route. Review applied (`f09e9f4`), checklist section 12 written. Q1's constants (growth 1.10, 60 ms attack, 220 ms release) await the user's verdict on a real take.

**Scope.** The whole feature, in 6 tasks: format and maths, the camera-less recorder, the image, the render, the live corner, closeout. It needs no measurement it cannot take in the first minute of Task 4, and nothing here waits on the user.

**Execution.** A fresh subagent per task (`superpowers:subagent-driven-development`), given this plan, the spec and `CLAUDE.md`.
- Tasks run one at a time, in the order written, in one tree. The cargo lock serialises every build anyway.
- The orchestrator runs the gate below and commits each task. It stages paths explicitly, never with `git add -A`.
- **At the end of every task the workspace builds and every test passes.** A task that changes a type fixes every user of it in the same task, in every crate.
- Each task writes its own `CLAUDE.md` addition, where it names one.

**The gate, for every task:** run the `verify` skill, with every cargo call under the machine-wide lock (`flock /tmp/claude-1000/cargo.lock nice -n 19 cargo …`), because other sessions build here too.

**Test-first.** Each task names the test that must fail first. Write it, run it and watch it fail for the stated reason, then build until it passes. A test that fails only because the code doesn't compile yet counts, but the plan names a behavioural failure wherever one exists.

**What tests may touch.** No test reaches the network, the real camera or the real microphone. Every recording test uses `CaptureKind::Test` / `CaptureSources::Test`; every image and every recording a test reads is generated by `fixtures`. No test reads the user's footage, and nothing that identifies a team, a player or a child goes into the repository — the repository is public.

## Task 1: The mode, the per-clip inset and the pulse maths (core, v10)

Core first, so every later task has the types and the numbers. No pixels and no files here.

**Files:**
- `crates/video-coach-core/src/{avatar.rs (new),lib.rs,project.rs,store.rs}`
- `crates/video-coach-core/tests/{avatar.rs (new),project_format.rs}`
- every `Clip { … }` literal: `grep -rn "Clip {" crates` (fixtures, harness, tests in all four crates)

**What to build:**
1. **`Inset`** in `project.rs`, beside `Resolution` and `Quality` (`:30-47`): a `camelCase` `#[derive(Default)]` enum, `Camera` the default, `Avatar` the other. `Clip.inset: Inset` with a field-level `#[serde(default)]`, beside `show_pip` (`:149`).
2. **`Project.avatar: Option<String>`** with a field-level `#[serde(default)]`, documented as *the mode*: `Some(file)` is an avatar project, `None` is a camera project (spec B1). The file name, never a path.
3. **`Clip::shows_camera_pip()` and `Clip::shows_avatar()`** (spec B3), written together with a comment that they are the two halves of one decision and that `show_pip × inset` is interpreted nowhere else.
4. **`add_recorded_clip` sets `inset: if self.avatar.is_some() { Inset::Avatar } else { Inset::Camera }`**, one line beside `show_pip` (`:430`).
5. **The bump: `CURRENT_FORMAT_VERSION = 10`.** `MIN_READABLE_FORMAT_VERSION` stays 7. Nothing else in `store.rs` changes.
6. **`avatar.rs`**, exactly the surface in spec D3: `PULSE_RATE`, `PULSE_GROWTH`, `PULSE_FLOOR_DB`, `PULSE_CEILING_DB`, `PULSE_ATTACK`, `PULSE_RELEASE`; `level_from_db`, `smooth(previous, target, dt)`, `pulse(samples_mono, rate, frames) -> Vec<f64>` (levels in `0..=1`), `avatar_rect(pip, level)`.
   - **Levels, never scales.** `PULSE_GROWTH` is applied in `avatar_rect` and nowhere else.
   - `smooth` picks `PULSE_ATTACK` while rising and `PULSE_RELEASE` while falling, `a = 1 − exp(−dt / τ)`. **Both estimators call it** — the render at `dt = 1/30`, the live corner at `dt = 0.1` — so it takes `dt` and holds no state.
   - `pulse` windows the samples per output frame (`[n/30, (n+1)/30)`), RMS, `level_from_db`, then `smooth` across frames from `s(−1) = 0`. A window past the end of the audio is silence.
7. **Fix every `Clip { … }` literal** in the workspace, in this task.

**Test that must fail first:**
- **`v7_to_v9_files_load_under_v10`** — grow the existing `v7_and_v8_files_load_under_v9` (`project_format.rs:265`) to a third raw file at v9 and assert, for all three, `avatar == None` and every clip `Inset::Camera`. It fails with `LegacyProject`… no: it fails on the **assertions**, because the field doesn't exist yet, and then on the version once the bump lands. Both are the point.
- `an_avatar_and_an_inset_round_trip` at v10, with the wire spellings (`"avatar"`, `"inset": "avatar"`).
- **`pulse`:** silence is all 0; a full-scale 200 Hz tone saturates at 1; a step from silence rises within two frames and decays over about seven; an empty slice, and a `frames` longer than the audio, give 0 tails; **every output is within `[0, 1]`** as a property over random input.
- **`smooth`:** rising uses the attack and falling the release (a step up reaches ~63% in `PULSE_ATTACK`); `dt = 0.1` and `dt = 1/30` converge to the same steady state; `dt = 0` changes nothing.
- **`level_from_db`:** the floor is 0, the ceiling is 1, and outside clamps.
- **`avatar_rect`:** `== pip` at `level == 1`; at `level == 0` it is centred on `pip` and `1/PULSE_GROWTH` of its size; monotone in `level`; **never exceeds `pip`** as a property over random levels (including out-of-range ones, which clamp).
- **`shows_camera_pip` / `shows_avatar`:** the four combinations, and never both true.
- **`add_recorded_clip`** takes `inset` from `project.avatar.is_some()`, both ways.

Do **not** clone `swift_era_v6_is_refused`, `newer_format_is_refused_as_too_new` or `write_stamps_the_current_format_version` for v10. They already cover the guard, and the third reads the constant.

**Verify:** the gate. Core's tests run on a machine with no GStreamer; nothing here may change that.

**CLAUDE.md:** a line in the format paragraph — v10 adds `Project.avatar` (which *is* avatar mode) and `Clip.inset`; the readable floor stays 7.

Commit: `feat(core): the avatar's mode, per-clip inset and pulse (format v10)`.

## Task 2: Recording without a camera

**Files:**

- `crates/video-coach-media/tests/` (the recorder's test file)

**What to build:**
1. **`CaptureSources` takes an optional video side on both arms** (spec C1): `Devices { camera: Option<Camera>, mic }` and `Test { video: Option<Duration> }`.
2. **`build` skips the whole video branch** when there is no camera: no source, no capsfilter, no `choose_encoder`, no `h264parse`, no video queue, and **no `video_%u` pad** in the mux loop (`recorder.rs:342-360`). `AUDIO_QUEUE_NS` stays as it is, with its comment extended by a clause: with no video pad the mux holds nothing, so the queue never fills.
3. **`FirstVideo` → `FirstBuffer`,** `Active.video_seen` → `media_seen`. A compiler-checked rename across the recorder, `bus/recording.rs` and the harness; do it here rather than in a task of its own. The flag is posted from the **one pad that exists** — the video pad when there is one, the audio pad otherwise — and its meaning is unchanged: a buffer reached the muxer, so there is a file worth keeping.
4. **`level_peak` → `level_dbs`,** returning `(peak_db, rms_db)`: the max over channels of each `ValueArray`. `RecorderMessage::Level { peak_db, rms_db }`, and `Event::Level` carries both. **The meter keeps drawing `peak_db`** (spec D1/G4) — this task adds the second number and changes no pixel.
5. **`capture_sources`** (`bus/recording.rs:274-296`):
   - an `avatar_mode()` helper on the bus: `open.project.avatar.is_some()`;
   - **the `CaptureKind::Test` early return honours it** (spec C1) — `Test { video: None }` in an avatar project, `Test { video: Some(video_delay) }` otherwise;
   - the `Devices` path resolves the microphone only in an avatar project, and **never calls `resolve_camera`**, so `NoCamera` cannot be raised there;
   - the camera-mode `NoCamera` message gains the way out: "no camera found — pick an avatar image in Devices to record without one".
6. **The start-timeout message** follows the mode (`bus/recording.rs:190-196`): "no sound from the microphone within 5 seconds" in an avatar project.

**Test that must fail first:**
- **Media, `an_audio_only_recorder_writes_a_playable_file`:** `CaptureSources::Test { video: None }` for ~1 s. It writes a Matroska that decodes with an audio track and **no** video track (`probe` says `NoVideo`); `t0_ns > 0`; `StopOutcome.duration` matches the audio's length; `self_view_pipeline()` is `None`; **`FirstBuffer` arrived**. It fails first because the variant and the shape don't exist.
- **Media, `the_level_message_carries_both_numbers`:** on a loud test tone, `peak_db > rms_db` and both are finite.
- **Harness, `an_avatar_project_records_without_a_camera`:** a project with `avatar` set, `CaptureKind::Test`, record and stop. The clip has `inset == Avatar`, and its recording has no video track.
- **Harness, `a_camera_project_still_records_with_one`:** the same, with no avatar. `inset == Camera`, and the recording has video. **These two together are the proof the `Test` arm honours the mode** — without the second, the first passes on a bug.

**Verify:** the gate. Media's recorder tests run on CI without a camera, as they do today.

**CLAUDE.md:** under the capture rules — an avatar project records audio only: no camera is opened, no video mux pad is requested, and no H.264 encoder is needed. `FirstBuffer` (not `FirstVideo`) is the first-buffer gate, and it comes from whichever pad there is. The `level` element's `rms` drives the avatar; its `peak` drives the meter.

## Task 3: The image — one decoder, picked, copied, removed

**Files:**
- `crates/video-coach-media/src/{lib.rs,fixtures.rs,composite/avatar.rs (new),composite/mod.rs}`
- `crates/video-coach-media/tests/avatar.rs` (new)
- `crates/video-coach-app/src/bus/{mod.rs,project.rs or wherever project edits live}`
- `crates/video-coach-app/src/main.rs`, `crates/video-coach-app/ui/app.slint`
- `crates/video-coach-harness/tests/avatar.rs`
- `packaging/smoke-test.sh`

**What to build:**
1. **`media::decode_still(path) -> Result<Still, String>`**, public on the crate (spec A3): `filesrc ! decodebin3 ! videoflip video-direction=auto ! videoconvert ! video/x-raw,format=RGBA,pixel-aspect-ratio=1/1 ! appsink`, bounded wait, **one** sample pulled, pipeline to NULL. `Still { w, h, rgba }` in **straight alpha**. Document it as the one avatar decoder: the pick validates with it, the corner draws with it, `avatar::open` scales its output.
   - `videoflip video-direction=auto` is what keeps an EXIF-rotated phone photo upright.
   - A multi-frame file yields its first frame and no error.
2. **`composite/avatar.rs::open(path, out_w, out_h) -> Result<Avatar, String>`:** `decode_still`, copy into a native-size `Pixmap` **premultiplying** (R,G,B × A/255 — `overlay.rs:26-31` says why), then scale **once** into a pixmap the size of `pip_rect(out_w, out_h, w/h)` rounded up, keeping the image's own shape (a square gravatar stays square). **Then mask it to a circle inscribed in that box** (spec A5), once at open time, so the draw is a plain blit. `Avatar { image, rect }` — **no stored `aspect`**; the rect carries it.
   - Add a test that a corner pixel of the fitted box is transparent and the centre is not.
3. **The bus commands:** `SetAvatar(PathBuf)` and `ClearAvatar`.
   - `SetAvatar`: `decode_still` first (refuse with the decoder's message, nothing copied), then copy the bytes to `<project>/avatar.<ext>` through a temp file + rename in the same directory, **deleting exactly the file `Project.avatar` names** if there was one — never a `avatar.*` glob — then set `Project.avatar` and save.
   - `ClearAvatar`: clear the field, delete the project's copy, save. The coach's original is untouched.
   - Neither is on the recording allow-list: the mode must not change under a running take.
4. **The Devices popover's Inset section** (`app.slint:3338-3364`), a third block under Microphone: the thumbnail and the file name, **Choose…** (an `rfd` file dialog filtered to PNG and JPEG) and **Remove**. With no image it reads "Camera — no avatar picked" and only **Choose…** shows. With the file gone it reads "`avatar.png` is missing".
5. **`fixtures::still_image(dir, name, w, h, format)`**: `videotestsrc num-buffers=1 ! videoconvert ! pngenc|jpegenc ! filesink`.
6. **`packaging/smoke-test.sh`:** add `pngdec` and `videoflip` to the element list (`:60-69`). They come from plugin sets the `.deb` already depends on, and the list is the only proof of that.

**Test that must fail first:**
- **Media, `decode_still_reads_a_png_and_a_jpeg`:** both fixtures decode to the fixture's dimensions; a non-square fixture keeps its aspect; a text file and a missing path each error with a message rather than panicking.
- **Media, `the_avatar_pixmap_is_premultiplied`:** a still with a half-alpha region (draw one into the fixture, or compose it), opened through `avatar::open`, has colour channels scaled by alpha — the failing-first form is the straight-alpha copy, which leaves them at full value. This is the test that catches the haloed cut-out.
- **Media, `an_avatar_is_a_circle_in_its_box`:** the fitted box's corners are transparent, its centre is not, and the boundary is where the inscribed circle puts it.
- **Media, `an_avatar_is_prescaled_to_the_inset`:** `open(path, 1920.0, 1080.0)` gives `rect == pip_rect(1920, 1080, w/h)` and a pixmap no smaller than it and no more than a pixel larger.
- **Harness, `picking_an_avatar_copies_it_into_the_project`:** `SetAvatar` on a fixture PNG leaves `<project>/avatar.png`, sets `Project.avatar`, and saves. A second `SetAvatar` with a JPEG leaves **one** image file (the PNG is gone) and no stray `.tmp`. A `SetAvatar` on a non-image is refused as a notice, copies nothing, and leaves `Project.avatar` as it was. `ClearAvatar` deletes the copy and clears the field.

**Verify:** the gate, plus a screenshot pass of the Devices popover in all three states (no image, an image, a missing image).

**CLAUDE.md:** under the project-folder rules — one avatar image per project, `<project>/avatar.<ext>`, copied in; `Project.avatar` **is** avatar mode; PNG and JPEG only, validated by decoding through `media::decode_still`, which is also the corner's decoder; GStreamer RGBA is straight alpha and tiny-skia is premultiplied, so the copy into the pixmap multiplies.

Commit: `feat(app): pick one avatar image per project`.

1. **`composite/avatar.rs::pulse_table(recording, frames, cancel) -> Vec<f64>`:** `Reader::start(.., PULSE_RATE, 1, cancel)` + `rest`, then `core::avatar::pulse`. A file with no audio, or one that won't read, gives all zeros — a flat avatar at rest, never a failed run. Delete the `#[allow(dead_code)]` Task 3 left on `Avatar` and `open`.
2. **Both jobs gain `avatar: Option<PathBuf>`**, a snapshot the bus takes from `open.folder.join(project.avatar)` — beside `scoreboard` and `highlights` (`export.rs:67-98`, `preview.rs:83-108`).
3. **Both tails open the image once** at their own output size (1920×1080, 1280×720) and **build their pulse tables in job setup**: export beside `Mixer::new(job)` (`export.rs:275`), one table per entry whose clip `shows_avatar()`, laid into one level per output frame for the run; preview once before its loop. **Not beside `Pip::open`** — that is inside the frame loop (`export.rs:309`), and a whole-file audio decode there stalls the pump.
4. **One level per output frame on the `Schedule`**, `1.0` wherever nothing pulses, and the inset pad's probe places `avatar_rect(entry.pip, level)` instead of `entry.pip` (spec E3). `avatar_rect` is exactly `pip` at `1.0`, so **a camera export is unchanged to the integer** and nothing branches. Both tails round a rect to a pad through **one** shared helper, preview included.
5. **Export uploads the avatar into GL memory once** (spec E2), through the hop `Filler` already takes — generalize that type to "a still RGBA image in GL memory" and let the filler be one transparent pixel of it. Each frame pushes `buffer.copy()` re-stamped: a new header over the same texture, no pixels touched. **System memory on that pad breaks `glupload` for a later entry with a real inset** (`export.rs:556-567`, reproduced).
6. **`Pip::open` branches on `core`'s two predicates, before the probe** (`export.rs:451-475`): `shows_avatar()` → the run's texture at `pip_rect` for the image's aspect, or the filler if the image is gone; `shows_camera_pip()` → the recording; neither → the filler. A missing image says so **once for the run**, not once per entry.
7. **Preview gets an appsrc branch for the avatar**, pushed from the pump beside the base and the overlay: `caps=RGBA,w,h ! glupload ! glcolorconvert ! mix.sink_1`, `stream-type=seekable` with the same `seek-data` callback, `wait_for_room` before the cursor's lock, EOS at the end of the schedule and `repeat-after-eos` on its pad. Its rect comes from a `BUFFER` probe keyed on PTS, never from the pushing thread.
8. **Preview's three recording-PiP sites take `shows_camera_pip()`**: `:564`, `:637`, `:894`. An avatar recording has no video pad to link.
9. **The inset pad blends premultiplied** — `blend-function-src-rgb=one`, in both tails, for the whole run (spec E4). An opaque camera frame blends identically either way, so there is nothing to switch at an entry join.
10. **`fixtures::solid_png(dir, name, w, h, colour)`**, so an export test can say "this pixel is the avatar" of a one-colour image. (`still_image`'s SMPTE bars share colours with every source fixture.)

**Test that must fail first:**
- **Media, `an_avatar_clip_pulses_in_the_export`:** a one-entry avatar compilation whose recording is a loud tone for its first second and silent for its second. Read frames back with `fixtures::decode_rgb` and measure the circle's width across the inset's centre row: on a loud frame it is `pip_rect`'s width, on a quiet one it is that over `PULSE_GROWTH`, and it never exceeds `pip_rect`. Frame count equals `plan.total_frames()`. It fails first on the field that doesn't exist, then on a still inset.
- **Media, `an_avatar_and_a_camera_clip_export_together`:** two entries, avatar first. The asserted frame count, no stall, and **each entry's own inset** — the caps change on the pad that used to fail an export outright. One direction only.
- **Media, `a_missing_avatar_image_costs_the_inset_not_the_run`:** the job's `avatar` points at a path that isn't there. The export completes with the full frame count and no inset.
- **Media, `an_avatar_clip_previews_without_stalling`:** a preview of an avatar clip produces frames, reaches its end within `STALL`, and shows the inset — round in its box. It fails first on the unrequested pad or the unlinked video pad if any of the three sites is missed. It then **scrubs**: one pipeline seek has to reach the avatar's appsrc too, or the graph refuses it and the preview retries it for ever.

## The user's own steps

They need a build, so they come after Task 6 and whatever release the orchestrator and the user agree on. Nothing in Tasks 1–6 waits on them.

1. **Pick an avatar.** Open a project, **Devices… → Inset → Choose…**, and pick a PNG or a JPEG. Check the thumbnail. Try a **portrait photo straight off a phone** — it must not come out sideways.
2. **Record a take with it.** Press R and talk. The corner shows the picture and it **breathes with your voice**: bigger on a word, settling between them. Say nothing for a few seconds — it should sit still, slightly smaller than a webcam inset would be, not disappear.
   - This works on a machine with no camera at all. If you have one, note that its light stays off.
3. **Check the preview**, then **export the clip.** The same picture, pulsing the same way, in the same corner. Draw over it while recording — the pen lands on top of it, as it does over a webcam.
4. **Try a cut-out PNG** (a transparent background) over a bright patch of pitch. **Your call:** is it legible, or does it want a plate behind it (Q3)?
5. **The one judgement only you can make (Q1):** does the pulse read as *talking*? The defaults are 10% growth, a 60 ms attack and a 220 ms release, over −45 to −12 dBFS. Too small reads as a wobble; too big reads as a cartoon. Say which way to move it — they are constants, so retuning costs a rebuild and changes no file.
6. **Mixed project.** Record one take on camera and one with the avatar in the same project, and export them together. Each clip shows what it was recorded with, and the inset never jumps size between them.
7. **Remove.** **Devices… → Inset → Remove** puts the project back on the camera, deletes the project's copy of the image, and **leaves your original file alone**. Clips already recorded stay avatar clips — they just have no picture until you pick one again.
8. **Going back.** The first save upgrades the project to format v10, which an older build refuses. `project.json.v9` beside it is the way back, losing the changes since.

## What stays deferred

Everything in the spec's Deferred list, until the user says otherwise:

- switching an existing clip between camera and avatar (Q5) — one `ClipEdit` variant, one checkbox, one undo case, and the spec says why it waits;
- more than one avatar per project, or a per-clip avatar;
- bounding the image decode by pixels rather than trusting that a real avatar is a few megabytes;
- a plate, border or rounded mask behind a cut-out (Q3);
- any other motion — a bob, a tilt, a mouth swap, two-frame talking;
- the avatar in the corner while scanning, outside a take (Q4);
- animated avatars: a multi-frame file yields its first frame;
- choosing camera-or-avatar per take at the Record button.
